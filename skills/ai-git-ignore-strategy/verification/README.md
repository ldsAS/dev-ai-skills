# 路徑主張查核與交接機制

本 skill 的正確性建立在一組**路徑事實**上：`.claude/settings.local.json` 是不是個人檔、
Antigravity 到底用 `.agent/` 還是 `.agents/`、對話紀錄在不在專案內。
這些事實會隨工具改版而變，且**多數無法從本機推斷**——必須到裝了該工具的環境實查。

本資料夾記錄每一條路徑主張的依據、取證時間、驗證者與狀態。

> 📌 本資料夾**不會被 `install.sh` 安裝**到使用者環境。
> 安裝器只複製 `skills/<name>/<variant>/` 底下的內容（見 `install.sh` 的 `install_skill_variant`）。

---

## 三種漂移，三種解法

| 漂移 | 誰負責發現 | 機制 |
| :--- | :--- | :--- |
| (a) 官方文件**改內容** | 自動 | `.github/workflows/check-updates.yml` 每日比對路徑 token，異動即開 issue |
| (b) 官方文件**搬家／下架** | 自動 | 同上，抓取失敗會標記 `CHECK_FAILED` |
| (c) 官方文件與**實機行為不符**，或版本落差 | **人工交接** | 本資料夾 |

自動機制只能證明「官方**文件**怎麼寫」。文件可能落後於實作、可能描述的是新版而你跑舊版。
(c) 類差異只有把問題送到實際裝了該工具的環境才問得出來。

## 為什麼要存摘錄，不能只存連結

URL 會爛、頁面會改版、同一段說明會搬到別的章節。只留連結的話，半年後回頭看
「當初依據什麼下這個判斷」就無從查證。

因此 [`CLAIMS.md`](./CLAIMS.md) 的「來源」欄一律要有**引述摘錄**，
而 `scripts/last_checked.json` 則保存了機器可比對的 token 快照。兩者互補：
摘錄給人看懂語意，token 給機器偵測異動。

---

## 最關鍵的一欄：工具版本

每一筆實機驗證**必須記錄回報者的工具版本號**。

沒有版本號的答案是不可證偽的：日後若官方文件與紀錄不符，無法判斷是
「文件寫錯」「當時版本較舊」還是「後來改掉了」。缺版本號的紀錄一律視為 `未驗證`。

---

## 狀態定義

| 狀態 | 意義 |
| :--- | :--- |
| `已驗證` | 有明確依據（官方文件摘錄，或含版本號的實機回報） |
| `待實查` | 需要到裝有該工具的環境確認，尚未進行 |
| `有疑` | 已有依據但彼此矛盾，或依據強度不足（例如僅 AI 自我回報、無檔案系統佐證） |
| `結構性` | 不是對外部事實的主張，而是讓白名單得以生效的規則（如 `.claude/*`），無需外部依據 |
| `被取代` | 已被新結論推翻，標註 `被取代→C-XX` 並**保留原列不刪除** |

> 結論改變時**新增一列**並把舊列標為 `被取代`，不要直接覆寫。
> 同一條路徑隔半年答案不同是常態，保留歷史才看得出變化軌跡。

## 一輪交接怎麼跑

```text
1. 從 CLAIMS.md 撈出 status = 待實查／有疑 的項目
2. 依 rounds/TEMPLATE.md 產生交接包  → rounds/YYYY-MM-DD-<tool>.md
3. 把交接包整份貼給該工具（它沒有本專案的任何上下文，包必須自帶背景）
4. 工具回填結果             → rounds/YYYY-MM-DD-<tool>.reply.md
5. 依回覆更新 CLAIMS.md，需要時同步修改五版 SKILL.md
6. commit：一輪一個 commit，訊息註明輪次與工具
```

交接包**必須同時附上「官方文件怎麼說」與「目前 skill 怎麼寫」**。
只問「這個檔案存在嗎」，工具無從判斷你要的是哪一版的行為；
把文件說法一起給它，它才能回答「我的環境跟文件不符」——這正是 (c) 類漂移唯一的抓取方式。

## 帳本與監控是連動的

`scripts/check_updates.py` 會讀取 [`CLAIMS.md`](./CLAIMS.md)，把偵測到的路徑異動
對應回帳本編號。偵測到異動時，issue 會直接寫出：

```text
- ❌ 消失：`~/.claude/projects/` → `C-07`

## 📒 受影響的帳本主張
- **C-07** `~/.claude/projects` — 狀態 已驗證，取證日 2026-07-29
  - 觸發：`~/.claude/projects/` 消失
  - 原主張：對話紀錄與 memory 在家目錄，不在專案內
```

不必再人工比對「這條 token 動了、到底影響哪些判斷」。
**路徑消失比新增更嚴重** —— 代表原依據可能已不成立，該條主張要重驗。

不屬於任何主張的新路徑會另列一區（🆕），那通常是全新機制，確認後要在帳本新增條目。

### 比對規則

- 帳本「路徑」欄的反引號路徑會被抽出來比對，**雙向前綴**皆算命中
  （token `.claude/rules/security.md` 命中主張 `.claude/rules/`，反之亦然）
- 含 `<name>`／`[_<N>]` 佔位符者截到第一個佔位符為止
- **單一段的目錄會被忽略**（如 `.agents/`、`.claude/*`）—— 否則該目錄底下任何異動
  都會被算成同一條主張，失去指向性。單段**檔名**（`.geminiignore`）則保留
- 所以新增主張時，「路徑」欄請填**具體路徑**而非描述文字，否則無法自動連動

### 查監控盲區

```bash
python scripts/check_updates.py --coverage
```

列出每條主張是否有監控 token 涵蓋。**沒有涵蓋的就是自動偵測照不到的地方**，
只能靠定期交接。目前盲區集中在 Antigravity 的 `.agents/*` 系列 ——
沒有公開文件的工具，監控自然也抓不到它的路徑異動。
