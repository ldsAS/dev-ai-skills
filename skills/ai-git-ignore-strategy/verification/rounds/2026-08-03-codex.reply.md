## ❌ 我方錯誤：`.codex/rollout.jsonl` 是範例 payload，不是真實路徑

先前我在 C-17 把 `.codex/rollout.jsonl` 列為「session 執行期紀錄」並在五版範本加了
explicit 排除規則。**那是錯的。** 該 token 的原始上下文是：

> For example, a SessionEnd command receives:
> `{ "session_id": "thr_123", "transcript_path": "/workspace/.codex/rollout.jsonl",
> "cwd": "/workspace", "hook_event_name": "SessionEnd", "reason": "other" }`

那是官方 hooks 文件裡**傳給 hook 的範例 JSON**，用的是虛構的 `/workspace/` 前綴 ——
不是「Codex 會在你的專案寫這個檔」。

實際位置經本機實查確認與回報一致：

```text
~/.codex/sessions/2026/08/03/rollout-2026-08-03T22-14-46-019fc7fa-....jsonl
~/.codex/sessions/2026/08/03/rollout-2026-08-03T22-15-52-019fc7fb-....jsonl
```

規格為 `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<timestamp>-<thread-id>.jsonl`，
`CODEX_HOME` 預設 `~/.codex`。**專案目錄沒有 `.codex/`。**

### 這是我一路在批評別人的同一種錯誤

前幾輪我反覆指出 Antigravity 的失效模式是「拿非觀察當觀察」。這次我自己犯的是同型：
**抽出 token 卻沒讀它的上下文，就當成路徑事實登記。** 監控機制的 token 抽取本來就
不區分「這是真實路徑」還是「這是文件裡的範例字串」—— 那是人該補上的判斷。

已在監控機制的定位上記下這個限制：**token 是線索，不是結論。**

誤植規則已自五版移除，並在原處留下註解說明為何移除（避免日後有人「補回來」）。

## ✅ C-12 採用：`.codex/skills` 不是官方 REPO 路徑

官方 skills scope 表（`learn.chatgpt.com/docs/build-skills`）：

| Scope | Location |
| :--- | :--- |
| REPO | `$CWD/.agents/skills`、`$CWD/../.agents/skills`、`$REPO_ROOT/.agents/skills` |
| USER | `$HOME/.agents/skills` |
| ADMIN | `/etc/codex/skills` |

`.codex/skills` 在該表**出現 0 次**。範本已加註為舊版相容路徑。

### 連帶發現：安裝器可能裝到 Codex 不讀的位置

官方 USER 路徑是 `$HOME/.agents/skills`，但本專案安裝器只寫 `~/.codex/skills`。
本機實查：`~/.codex/skills/` **只有我方安裝的那一個技能**，而 `~/.agents/skills`
**根本不存在** —— 與 C-48 完全同型的循環證據。

依 C-48 的教訓（誤判導致技能在 IDE 端失效），採**兩條都寫**：
`~/.codex/skills`（舊版相容）＋ `~/.agents/skills`（官方 USER，且為 Gemini CLI 與
Copilot 共用）。實測假 HOME 只有 `.codex` 時兩條路徑皆正確寫入。已登記為 C-64。
