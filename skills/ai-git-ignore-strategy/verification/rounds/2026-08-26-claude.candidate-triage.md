## 三、三個值得記下的發現

### 3-1　`synced` 是保留名稱，不只是家目錄路徑

官方 skills 頁：

> The folder name `synced` is **reserved in the enterprise, personal, and project skills
> locations**, in any capitalization. Claude Code downloads the skills you enable on claude.ai
> into `~/.claude/skills/synced/` when `CLAUDE_CODE_SYNC_SKILLS` is set in non-interactive
> mode, and **skips a skill you author at that name**.

**兩層意義**：

1. 下載內容落在家目錄，不進專案 → 無需新增規則。
2. **專案層 `.claude/skills/synced/` 同為保留名。** 本技能建議寫 scoped allowlist
   （`!.claude/skills/<project-skill>/`）時，`synced` 是**不可用的名稱** ——
   取此名會被工具**靜默略過**。

若只把它當成「又一條家目錄路徑」就會漏掉第 2 點。現行範本以 `.claude/skills/*`
擋下，行為已正確（專案層本來就不該出現此目錄），故範本無需異動。

### 3-2　只憑 token 登記會把用途寫窄　→ ⚠️ 本節的教訓已於 8-6 更正

> 📌 **下方的實查觀察正確，但當時推出的教訓是錯的。**

## 八、補正：一個被抽取器截短而漏掉的候選（2026-08-26）

### 8-1　Codex 發現什麼

2026-08-22 的 Antigravity changelog 原文是：

> Fixed `@` file path completion showing files that were in your `.antigravityignore`.

但 baseline 存進去的是 **`.antigravity`** —— 被截短了。因此該候選從未以正確檔名
出現在任何報告中，本文初版的「全數分類完成」自然也就漏了它。

### 8-2　成因：漏列一個長名，代價是靜默截短

`TOKEN_RE` 的 alternation **取最先命中者**，所以 `DOT_NAMES` 中長名必須排在其前綴之前。
程式碼原本就註明了這條規則：

```python
# 長名必須排在短名前面：alternation 取最先命中者，
# 否則 `.agents` 會先被 `.agent` 吃掉、`.codexignore` 會被 `.codex` 吃掉。
```

`geminiignore`、`codexignore` 都正確列出且順序無誤，**唯獨 `antigravityignore` 漏列**。
漏列的後果不是「漏抓」而是「**存進錯的值**」—— 不會報錯，報告看起來也完全正常。

### 8-3　修法：已知長名排序＋未知長名右側邊界

第一輪不只加 `"antigravityignore"`，也加了**排序不變式測試**：

```python
def test_longer_dot_names_precede_their_prefixes(self):
    """若 A 是 B 的前綴，B 必須排在 A 之前，否則 alternation 會先命中 A。"""
    names = MONITOR.DOT_NAMES.split("|")
    for i, short in enumerate(names):
        for j, long_ in enumerate(names):
            if long_ != short and long_.startswith(short):
                self.assertLess(j, i, f"{long_!r} 必須排在 {short!r} 之前…")
```

它能保護**清單內已知名稱**的順序，但 Codex 第二次複驗證明，還不能阻止
未列入清單的更長名稱被截短：

```text
.antigravityignored     → .antigravityignore
.antigravity-new-file   → .antigravity
.agentsfoo              → .agents
.geminiwhatever         → .gemini
```

因此 dot-name 分支再補上**右側邊界**：不允許已知 token 後緊接字元、連字號，
也不允許 `.` 後再接檔名字元（如 `.bak`）；單獨的句尾 `.` 仍允許。測試已改為
比對完整 token set，並新增 6 個負向案例。排序不變式仍保留作為已知名稱的第二層防護。

### 8-4　`.antigravityignore` 的分類（C-94）

在 **8 個** Antigravity 官方來源中全文檢索，**僅 changelog 一處提及**，且是修復說明。

| 已確認 | 未確認 |
| :--- | :--- |
| 工具會依此檔排除 `@` 檔案路徑補全的候選 | 檔案位置（專案根目錄／家目錄） |
| | 是否團隊共用 |
| | 與 `.geminiignore` 的關係（`gcli-migration` 頁 0 次提及 ignore） |

**刻意不以 C-23（`.geminiignore`／`.aiexclude`）類比補齊** —— 那正是本專案禁止的。
現行範本**沒有阻擋此名稱**；因檔案位置與分享定位未定，本輪維持現狀、不新增規則，
也不宣稱它與其他 ignore 檔具有相同處置。故五版 SKILL.md 仍無需異動。
