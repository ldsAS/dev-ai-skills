## 複驗 ①　`check_updates.py --coverage` @ Windows CP950

### ⚠️ 第一次執行不算數

直接跑 `python scripts/check_updates.py --coverage` 得到 exit 0，看起來通過 ——
**但那次執行根本沒有重現 CP950 條件**：

```
PYTHONUTF8        = ''            ← 確實未設定
PYTHONIOENCODING  = 'utf-8:surrogateescape'   ← ❗ 被工作階段設成 UTF-8
主控台 codepage   = 65001          ← ❗ 是 UTF-8，不是 CP950
```

`PYTHONIOENCODING` 會直接決定 `sys.stdout.encoding`，優先於 codepage。
在這種環境下，**修正前的版本也不會崩潰**，所以那次「通過」不具證據力。

### 重建真正的重現條件

清掉兩個環境變數並把 stdout 導向檔案（此時 Python 取 locale preferred encoding）：

```powershell
cmd /c "set PYTHONIOENCODING=&& set PYTHONUTF8=&& python -c ""import sys;print(sys.stdout.encoding)""" > enc.txt
# → cp950
```

### 決定性測試：修正前後同時測

只測修正後版本無法排除「我的重現環境本身無效」，所以**兩邊都跑**：

```powershell
git show 7635593^:scripts/check_updates.py > scripts\_prefix_check.py

# A. 修正前
cmd /c "set PYTHONIOENCODING=&& set PYTHONUTF8=&& python scripts\_prefix_check.py --coverage" > a.txt 2>&1
# B. 修正後
cmd /c "set PYTHONIOENCODING=&& set PYTHONUTF8=&& python scripts\check_updates.py --coverage" > b.txt 2>&1
```

| 版本 | exit | 輸出 |
| :--- | ---: | :--- |
| `7635593^`（修正前） | **1** | `UnicodeEncodeError: 'cp950' codec can't encode character '↔' in position 5`<br>接著 `... '❌' in position 3`（例外處理中二次崩潰） |
| `7635593`（修正後） | **0** | `可自動偵測 45 條／盲區 2 條／共 47 條有路徑的主張` |

兩次崩潰的順序（先 `↔` U+2194、再 `❌` U+274C）與你交接檔描述的
「進入例外處理後又因輸出 ❌ 再崩潰一次」**完全吻合**。

修正本身也確認在程式碼中，且有 `hasattr(..., "reconfigure")` 保護：

```python
for _stream in (sys.stdout, sys.stderr):
    if hasattr(_stream, "reconfigure"):
        _stream.reconfigure(encoding="utf-8")
```

**→ 複驗通過。** 45 條自動偵測／2 條盲區的結果亦如宣稱維持不變。

## 我自己在複驗過程中犯的兩個判讀錯

兩次都是**我的檢查腳本有 bug**，不是你的程式碼有問題。寫下來是因為任何人重跑
這套檢查都可能踩到同樣的坑：

### 1. 誤報「`ls-files --error-unmatch` 缺失」

我只掃了第二段 ` ```yaml ` block 就下結論。實際上它在**另一段 fence** 裡，
五版各有 1 處。

> 教訓：檢查「某要素是否存在」時，搜尋範圍要是整份檔案，不是某一個抽取出來的區塊。

### 2. 誤報「6 行指令裸露在 fence 外」

我的 fence 偵測器用 `^\`\`\`` 比對，**漏掉 Markdown 合法的縮排 fence**
（CommonMark 允許最多 3 個前導空格）。`generic/SKILL.md` 第 194／198 行正是縮排
3 空格的 ` ```bash ` 區塊。

改成 `^\s{0,3}\`\`\`` 之後，五版的 fence 總數從 20/24 修正為 28/36，
裸露指令行歸零。

> 教訓：這與本技能一貫關注的失效模式同型 —— **檢查工具本身出錯時是靜默的**，
> 只會給出「看起來合理」的結論。
