### P2：抓取失敗的舊 baseline 被說成目前仍有來源

位置：[PR #14 check_updates.py](https://github.com/ldsAS/dev-ai-skills/blob/67d942ea3471636900e8e9f122a23e9810df8b4c/scripts/check_updates.py#L570)。移除 token 的跨來源註記拿 `new_sources` 查找，而這個表也裝著失敗來源保留下來的舊 baseline。故無法支持「此路徑目前仍出現在」的斷言。

離線重現輸入：A 舊有 `.claude/hooks/` 和 `.claude/settings.json`、本輪只剩 settings；B 舊有 `.claude/hooks/`、`.claude/rules/`、`.claude/skills/`，本輪拋出 `RuntimeError("fixture outage")`。使用真正 PR main()，只 mock fetch／版本來源與暫存 baseline，執行 `--dry-run`。輸出同時有 `CHECK_FAILED`，也有「目前仍出現在 claude-code/b」；現有 41 項測試沒有抓到，因 fake_fetch 只能讓所有來源一起失敗。

修正方向：將「本輪成功抽取」的來源與「失敗沿用」分開；只有成功來源能證明當前存在。舊 baseline 可另列「上次存在，本輪未驗證」，不能作為目前仍存在的依據。至少補部分來源失敗、空集合保護與成功來源仍存在三種案例。此修正屬 PR #14 後續，本輪沒有偷偷帶入其程式。

## 4. Workflow dry-run 與驗收證據
