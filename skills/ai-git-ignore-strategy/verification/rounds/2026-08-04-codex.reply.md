## Q1. 現在載入得到 `ai-git-ignore-strategy` 嗎？

**結論：可以，而且實際是從 `~/.agents/skills/` 載入。**

目前 task 在 2026-08-09 產生的 skill root／catalog 明列：

```text
r0 = C:/Users/LdsFi/.agents/skills
r1 = C:/Users/LdsFi/.codex/skills/.system

ai-git-ignore-strategy
  file: r0/ai-git-ignore-strategy/SKILL.md
```

展開後的絕對路徑是：

```text
C:\Users\LdsFi\.agents\skills\ai-git-ignore-strategy\SKILL.md
```

該路徑是實體目錄，不是 symlink；目前 `C:\Users\LdsFi\.agents\skills\` 下只有這一個 skill。

因此，刪除下列舊複本後，Codex 端的技能**沒有消失**：

```text

```

## `~/.codex/skills/` 目前內容與掃描判讀

`C:\Users\LdsFi\.codex\skills\` 目前只有 `.system/`；不存在 `ai-git-ignore-strategy/`。`.system/` 內容為：

```text
.codex-system-skills.marker

```

目前 task 的實際 root 登記將兩者明確分開：

| 用途 | 實際 root | 判讀 |
| :--- | :--- | :--- |
| 使用者技能 | `C:\Users\LdsFi\.agents\skills` | 有掃描；本技能從此處載入 |
| Codex 內建系統技能 | `C:\Users\LdsFi\.codex\skills\.system` | 有載入 |
| `.codex\skills` 父目錄作為一般 USER root | 未出現在目前 task 的 root 清單 | 不應再當成現行 USER 安裝路徑 |

所以「Codex 會不會掃 `~/.codex/skills/`」必須拆成兩句：

1. `~/.codex/skills/.system/`：**會使用**，這是目前內建系統技能所在處。
2. `~/.codex/skills/<user-skill>/`：目前 task 沒有把父目錄登記成 USER root；現行官方 USER 路徑與本機實際載入來源都是 `~/.agents/skills/`。

本輪沒有為了測試而在 `~/.codex/skills/` 人工塞入一個探針 skill，因此不宣稱所有舊版本、所有啟動模式都「絕對不可能」保留 legacy fallback；但對本次刪除是否安全，已有實際載入成功可直接證明，信心為**高**。

官方現行 scope 表亦一致：

- REPO：從 CWD 往 repository root 掃描各層 `.agents/skills`
- USER：`$HOME/.agents/skills`
- ADMIN：`/etc/codex/skills`
- SYSTEM：Codex 內建

## 全域或專案層的 Codex 判斷

對 `ai-git-ignore-strategy`，建議預設採用**全域使用者層**：

```text
$HOME/.agents/skills/ai-git-ignore-strategy/
```

理由是它是跨 repository 使用的通用 Git 稽核流程。只有下列情況才建議放進專案：

- 團隊要把特定版本與專案一起提交、審查及傳承。
- 工作流程真的具有專案專屬內容，而不只是幾條本地規則。
- 所有團隊成員都應在該 repository 自動取得同一份 skill。

專案層位置應為：

```text
<repo>/.agents/skills/ai-git-ignore-strategy/
```

Codex 官方明載：同名技能**不會合併**，兩份都可能出現在 selector。因此不建議同時維護「全域同名版＋專案同名版」。若只是少量專案規則，應優先寫進根目錄 `AGENTS.md`；若確實需要另一套專案技能，應使用可區分的名稱，或明確停用其中一份。

對 `dev-ai-skills` 這個來源 repository 本身，canonical source 維持在：

```text
skills/ai-git-ignore-strategy/<variant>/SKILL.md
```

Codex 執行時再由安裝器複製 generic 版到全域 `~/.agents/skills/`，不需要在本 repo 額外建立同名的 project copy。
