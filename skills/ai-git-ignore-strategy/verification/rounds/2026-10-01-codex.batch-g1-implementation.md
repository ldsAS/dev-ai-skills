## 收尾自查：交付正文也必須相同

自查發現僅核對 SHA marker，不能證明 GitHub 上仍保存相同正文：人工改掉規則報告卻保留 marker，原實作會誤認已交付。修法將原有可見規則報告包在唯一的 begin/end HTML marker 內，核對 marker、SHA 與實際規則正文；不重複顯示報告。顯示版必須恰含一份規則版，否則拒絕交付。open 的正文被改動則修回並重查；closed 的正文被改動則停止 baseline 寫回。

新增真通知 CLI／fake API／真 baseline guard 整合反例：保留 SHA、只改正文，open 必須 edit、closed 必須阻擋。`python -X utf8 -B -m unittest discover -s tests -p test_monitor_delivery.py` **14 tests 通過**。暫存副本將實際正文比較還原為只看 SHA，`-k sha_marker` **1 test、1 failure，exit 1**；工作檔未放突變。這是 G1 原交付契約的補強，不新增偵測、baseline 欄位或跨 run 去重。

收尾亦補齊既有 verify-monitor workflow 的 push／pull_request path filter 與 py_compile 清單，涵蓋新 notification 腳本，避免日後只改此檔時離線 CI 沒被啟動。YAML BaseLoader 解析成功，兩個事件的 path matching 與編譯清單均核對通過；本機只讀 YAML，沒有觸發 workflow。
