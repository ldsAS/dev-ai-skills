## 一、背景（沒有上下文的話請先讀）

### 這個 repo 在做什麼

`dev-ai-skills` 提供一個 skill：`ai-git-ignore-strategy`，教各種 AI 工具（Claude Code、Codex、Gemini CLI、Antigravity、VS Code Copilot）判斷**哪些 AI 產生物該進 git、哪些不該**。核心產出是一份 `.gitignore` 範本。

- 五個變體：`skills/ai-git-ignore-strategy/{antigravity,claude,codex,generic,vscode}/SKILL.md`。**五版必須同構**：邏輯一致，只有工具名可以不同。改規則就五版一起改。
- 範本的正確性建立在一組**路徑事實**上，例如 `.claude/settings.local.json` 是個人檔、應排除。

### 三個互相連動的機制

| 機制 | 檔案 | 作用 |
| :--- | :--- | :--- |
| 路徑主張帳本 | `verification/CLAIMS.md` | 記錄每一條路徑事實的主張、依據摘錄、取證日、狀態。C-01～C-99 已在 `main`，C-100～C-102 在 PR #14 |
| 每日監控 | `scripts/check_updates.py` ＋ `.github/workflows/check-updates.yml` | 抓官方文件、抽出路徑 token，與 `scripts/last_checked.json` 的 baseline 比對，有異動就開 issue |
| 範本驗證 | `scripts/verify_gitignore_template.py` | 把五版範本各自寫進暫存 repo，用 `git check-ignore --no-index` 逐案驗證「擋／放行」 |

### 本 repo 的處理慣例（照這些做，結論才會被採信）

- **D6**：分類候選 token 時，不讀 issue 裡被截斷的摘錄，一律用監控自己的 `fetch()` + `normalize()` + `context_for()` 重新抓官方原文。
- **C-89**：斷言要驗證過才算數。實際把修正還原，確認指定的測試**真的會轉紅**。
- **結論改變時新增一列，把舊列標成「被取代」**，不要直接覆寫。
- `install.ps1` 必須維持 **UTF-8 with BOM**（Windows PowerShell 5.1 讀無 BOM 的中文會 parse 失敗）。
- 行尾一律 LF（`.gitattributes`：`* text=auto eol=lf`）。

這 4 條**不是**本週的新訊號，是我回頭用官方頁核對時發現的。**五個變體都一樣錯**（逐版實測過）。

| 1 | `.claude/CLAUDE.md` | memory 頁表格：「**Project instructions** \| `./CLAUDE.md` or `./.claude/CLAUDE.md` \| Team-shared instructions for the project \| … \| Team members via source control」 | **擋** | 放行 | 團隊指令被靜默排除 |

| 3 | `.claude/agent-memory/` | claude-directory 頁：「This directory holds project-scoped subagent memory, **meant to be shared with your team**. To keep memory out of version control use `memory: local`, which writes to `.claude/agent-memory-local/` instead.」 | **擋** | 放行 | 團隊共享的 subagent 記憶被排除 |
| 4 | `CLAUDE.local.md` | memory 頁表格：「**Local instructions** \| `./CLAUDE.local.md` \| Personal project-specific preferences; **add to `.gitignore`**」；另載「Files in subdirectories load on demand」 | **放行** | 擋（含子目錄） | 個人筆記（sandbox URL、偏好的測試資料）會被提交 |

前 3 條跟 C-83（`.claude/launch.json`）是同一類 bug：共享檔被 `.claude/*` 靜默擋掉。第 4 條方向相反，是個人檔外洩。

### 為什麼拖這麼久才發現

`.claude/CLAUDE.md` 從 **2026-07-29** 就在 baseline 裡，而且來源是**有受監控**的 `claude-code/memory`。沒被抓到有兩個原因：

1. **監控只對「變動」有反應。** 建立 baseline 時就已存在的 token，從來沒有人拿去跟範本比對。
2. **C-62 的噪音遮住了它。** `.claude/CLAUDE.md` 與 `.claude/hooks/helper.sh` 一直被標成 C-62，看起來「有對應主張」，其實就是 C-100 修掉的那種往上誤命中。PR #14 會移除噪音，但**不會回頭補分類**。

我把 baseline 裡 82 個專案層 token 全部跑過一遍：54 個有主張，28 個沒有。那 28 個之中，除了上面 4 條，其餘都是文件範例、語彙別名，或原本就是刻意的設計（例如 `.gemini/skills/*` 是 scoped allowlist，跟 `.claude/skills/*` 是同一套設計）。

### 提案規則（只在暫存 repo 測過，未提交）

插在各變體的 `!.claude/workflows/` 之後：

```gitignore
# 專案指令檔的第二個合法位置，官方定位為團隊共享（C-103）
!.claude/CLAUDE.md
# hook 腳本：提交的 settings.json 以 ${CLAUDE_PROJECT_DIR}/.claude/hooks/… 引用它們（C-104）
# ⚠️ 內含可執行指令，提交前應審查（比照 C-76 對 .github/hooks 的處置）
!.claude/hooks/

#    預期：前 3 個路徑為 IGNORED、兩個 CLAUDE.local.md 為 ALLOWED——也就是現行範本的錯誤
import re, io, subprocess, tempfile, pathlib
probes = [".claude/CLAUDE.md", ".claude/hooks/block-rm.sh",
          ".claude/agent-memory/reviewer/MEMORY.md", "CLAUDE.local.md", "apps/web/CLAUDE.local.md"]

    s = io.open(f"skills/ai-git-ignore-strategy/{v}/SKILL.md", encoding="utf-8").read()
    tpl = [b for b in re.findall(r"(?ms)^```[a-zA-Z]*\n(.*?)^```$", s) if ".claude/*" in b][0]
    d = tempfile.mkdtemp()
    subprocess.run(["git", "init", "-q", d])
    pathlib.Path(d, ".gitignore").write_text(tpl, encoding="utf-8")
    res = ["IGNORED" if subprocess.run(["git", "-C", d, "check-ignore", "--no-index", "-q", "--", p]).returncode == 0
           else "ALLOWED" for p in probes]
    print(v, dict(zip(probes, res)))
```
